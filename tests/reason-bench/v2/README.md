# reason-bench v2

Second iteration, built from v1's lessons (`../results/results.md` §lessons):
harder composed traps, execution grading where possible, and **fable added as
a benched subject** to establish the target line the skill claims to close.

## Matrix

- **Models:** haiku, opus, **fable** (sonnet dropped — in v1 all tiers tied
  31–32/35; it added no signal)
- **Conditions:** `base` (task only) vs `scaffold` (task + `scaffold.md`,
  re-extracted from the post-overhaul skill: shape rule, Quantify and
  spec-sweep in Attack, breadth-first enumeration)
- **Problems:** two, hardened (user call 2026-07-29: fewer, harder):
  - **p6 coding** — timezone/anchor billing-date arithmetic, graded by
    executing baked probes. Composes month-end anchoring × DST gap/fold ×
    UTC conversion, a documented model-weak surface.
  - **p7 architecture** — usage-metering → immutable invoices. Every trap
    requires composing ≥2 spec constraints and most require magnitude math.

12 runs. Problems remain self-contained: model knowledge only, no shell/web.

## Known bias — disclose with any result

The problem author, the grader, and one subject (fable) are the same model.
Subject runs are fresh agents with no access to `grading/` or this session,
so they cannot see the traps — but traps a model *authors* are traps it finds
natural to *think of*, which inflates fable-as-subject relative to a
neutrally-authored bench. Mitigations: p6 is graded by executing baked probes
(ground truth generated by running a reference implementation, not judgment),
and p7 traps are drawn from documented real-world failure classes
(billing-anchor bugs, late-event invoicing, price reproducibility) rather
than free invention. Treat fable-vs-others deltas as an upper bound.

## Run protocol

For each cell, launch a fresh agent with the target model:

> Read `problems/pN-task.md` and complete the task it contains, using only
> your own knowledge. Read ONLY the file(s) named here; Write ONLY your
> answer file(s). No other tools, no shell, no web.
> Answer file: `results/raw/<model>-<condition>-pN.md`.

Scaffold condition adds: read `scaffold.md` first and follow it — name the
deliverable's shape, then write every move as a visible section before the
deliverable. p6 additionally writes `billing.py` + `test_billing.py` to
`results/raw/<model>-<condition>-p6/`.

Subjects must never read `grading/`.

## Grading

p6: run `grading/p6_probe.py <submission-dir>` — 6 probe points with
expected outputs baked from an executed reference implementation
(`grading/p6_reference.py`), + 2 rubric points for the submission's own
test coverage. p7: per-trap binary ("resolves, not mentions") vs
`grading/p7-rubric.md`, 8 traps. 16 pts total. Report scaffold−base per
tier, and each tier vs fable-base (the target line).
